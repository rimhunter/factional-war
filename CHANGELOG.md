# Changelog

This is a modified version of "Factional War" by Shadowrabbit (Shadowrabbit/FactionalWar, last commit 3d35b55 "v1.4 support", 2022-10-22, tagged `original-1.4` in this repository), under the Apache License, Version 2.0. This file lists every change from that commit, with its date. Original copyright and license: see LICENSE, NOTICE and MODIFICATIONS.

The continuation is built from Shadowrabbit's own source. No DLL of any build was used. Fixes taken from Ionfrigate12345's 1.5 continuation or llunak's 1.6 fork are listed below with the author named.

Add each new change under "Unreleased" with its date as `- YYYY-MM-DD: what changed`. At release, rename the heading to the version and release date.

## 1.1.0 (2026-11-18)

- 2026-11-18: builds for RimWorld 1.6 and 1.7 from one source, into the `1.6` and `1.7` load folders, selected by `LoadFolders.xml`; `About/About.xml` supports 1.6 and 1.7 (the original supported 1.2, 1.3 and 1.4). The mod references only the game, through the Krafs.Rimworld.Ref package.
- 2026-11-18: the per-version folders `1.2`, `1.3` and `1.4` are gone. Their `Defs` were identical and are shared at the root (`Defs/`); the 1.4 source is the base (`Source/`). The prebuilt `Assemblies/ModRimWorldFactionalWar.dll` files, the bundled game libraries `Lib/Assembly-CSharp.dll` and `Lib/UnityEngine.CoreModule.dll`, `obj/`, the solution files, `Properties/AssemblyInfo.cs` (the SDK generates it) and `IncidentWorkerPoaching.cs.rej` are no longer committed.
- 2026-11-18: compile fix taken from llunak's 1.6 fork, commit 1974241 (2025-06-12, "make build with 1.6"): `IncidentWorkerFactionWar.FactionCanBeGroupSource` overrides the new public `(Faction, IncidentParms, bool)` signature, both `CandidateFactions` calls take `parms`, `AdjustedRaidPoints` is passed `parms.target`, and `JobGiverAISapper` calls `PathFinder.FindPathNow` in place of the removed `FindPath`. Each change was re-checked against the 1.6.4871 and 1.7.5005 game libraries.
- 2026-11-18: compile fix taken from Ionfrigate12345's 1.5 continuation, commit df1946e (2024-04-12, "Factional War Continued 1.5"): `LordToilShell` calls `Blueprint_Build.TotalMaterialCost()` in place of the removed `MaterialsNeeded()`. Re-checked against the 1.6.4871 and 1.7.5005 game libraries.
- 2026-11-18: identity. The mod is "Factional War (rimhunter)" with packageId `rimhunter.factionalwar` (the original's was `SR.ModRimworld.FactionalWar`), version 1.1.0, author "Shadowrabbit, Ionfrigate12345, llunak, rimhunter" and its own `<url>`. `About/About.xml` has no `modDependencies`, keeps `loadAfter` `Ludeon.RimWorld`, supports 1.6 and 1.7 in `supportedVersions`, and lists `incompatibleWith` for `SR.ModRimworld.FactionalWar` (the original) and `SR.ModRimworld.FactionalWarContinued` (the 1.5 continuation and the 1.6 fork, which share that id), so RimWorld's mod list warns when one of them is enabled with this mod.
- 2026-11-18: removed `About/PublishedFileId.txt`, which held the original's Workshop item id. This mod's Workshop id is recorded when it is first uploaded.
- 2026-11-18: license and credit. `LICENSE` is the original file, unchanged. `NOTICE` and `MODIFICATIONS` serve as the per-file notice that Apache License 2.0 section 4(b) asks for (the changed .cs files are not edited to carry one). New `NOTICE` (attribution and the Apache License 2.0 statement), `MODIFICATIONS` (the modification notice) and this changelog. The description credits Shadowrabbit, Ionfrigate12345 and llunak and says rimhunter claims no ownership of the original.
- 2026-11-18: new `Readme.md` and `WORKSHOP.md` (the Steam BBCode page text) that credit the original and each continuer, state the license, take no donations and list which Workshop builds to unsubscribe from first.
- 2026-11-18: new preview image `About/Preview.png`, drawn by rimhunter with `scripts/make-art`. The original's preview image (credited on its Workshop page to another artist, with no license published) is no longer in the tree.
- 2026-11-18: new icons at the six paths under `Textures/World/WorldObjects/Sites/` (`FactionTempCamp`, `FactionTempCampExpand`, `FactionWarContention`, `FactionWarContentionExpand`, `FactionWarShelling`, `FactionWarShellingExpand`), drawn by rimhunter with `scripts/make-art`. The original's icons (credited on its Workshop page to another artist, with no license published) are no longer in the tree. The defs point at the same paths and are unchanged.
- 2026-11-18: translations. Every language folder of the original is kept with every key unchanged (Chinese Simplified and Traditional, English, French, German, Japanese, Korean, Polish, Portuguese Brazilian, Russian, Spanish Latin). `Languages/PortugueseBrazilian/DefInjected/SitePartDef/FactionWarShelling.xml` began with a tab before the XML declaration, which the game cannot parse; the tab is removed.
- 2026-11-18: `About/About.xml` now says rimhunter will hand the mod back, or take it down, at Shadowrabbit's request, as `WORKSHOP.md` already did; `scripts/test-identity` checks the sentence.
- 2026-11-18: the description text corrects "hositle" to "hostile".
- 2026-11-18: `scripts/package` writes `dist/rimhunter.factionalwar` and ships `NOTICE`, `MODIFICATIONS`, `CHANGELOG.md` and the folders for each game version with `Source/`; it never ships the test runner, the tests, `Readme.md`, `WORKSHOP.md` or a `PublishedFileId.txt`. New `scripts/test-identity` checks the identity, license, translations, art, Workshop text and package contents.
- 2026-11-18: battles between two NPC factions never pick a hidden faction (the Ancients) or the player's faction as a combatant. The original's `FactionExtension.IsFactionEffective` did not check either, so Faction Assault sometimes sent the hidden Ancients against a faction. Every incident chooses its sides through that check. A pawn that could not be given a goto job is no longer handed the same dead job ten times in one tick (the log error "started 10 jobs in one tick"). Fixed by rimhunter, not taken from another build.
- 2026-11-18: arriving at a battle site shows both sides fighting. The three site incidents (Faction Bombardment, Faction Contention, Faction Defense) chose their two factions only when the player arrived, and anything that went wrong then returned silently: the player reached a map with no battle, or only mechanoids. The pair is now chosen before the site is made, stored on the site and saved with the game; an incident with no valid pair or tile does not fire and logs a warning, and a failure to place the pawns logs an error and drops the whole battle. The site's own `PostMapGenerate` base call runs again, with the site's 4-day detection raids switched off. Leaving a battle no longer destroys it: the map and the site stay while both sides still have a standing pawn (up to 90000 ticks) and the fight goes on while you are away; when one side is gone the site is removed. Written by rimhunter from the game's own code, not taken from another build.
- 2026-11-18: playing as a bystander is recorded, not changed. The mod has no goodwill code: hurting a pawn of a side that is not hostile to you costs what the game charges, tending a downed pawn that its side then carries off pays what the game reports, and a side at peace with you never targeted your pawns in any battle kind. A side hostile to you that you damage turns on you, as in the original. Dead pawns drop their gear forbidden (the game's own rule, one click to allow), corpses stay, the reform caravan button is disabled with its keyed text while a friendly side is collecting loot, and quests tied to a site get their signals. No source change; the behavior is covered by scenarios.
- 2026-11-18: DLC fixes by rimhunter, written from the game's decompile and not taken from another build. Anomaly: a faction whose fighters are shamblers left at once, because pawn generation moved every shambler to the Entities faction and the mod read the side as beaten on the first check; the mutants are put back into the faction's group. Royalty: the winners (the Empire, for example) stopped and wandered the map for good when one beaten pawn was alive but unreachable; the transition to clearing the battlefield now ignores a beaten pawn that no winner can reach. Odyssey: Faction Assault no longer picks a faction whose arrival modes forbid walking in (the Traders Guild), which logged "Could not resolve arrival mode for raid". Ideology and Biotech factions were checked and fight as they should.
- 2026-11-18: settings. The two settings of the original are unchanged in name and range: "Enable optimization" and "Threat point factor" (10% to 200%, default 100%). "Enable optimization" now starts on in a fresh install, as its settings window, its Default button and its saved value already said (the field default was off). The threat point factor is checked against its bounds. A stray line of text after `</WorldObjectDef>` in `Defs/WorldObjectDef/WorldObjects.xml` is removed. Saved settings are written when the window closes and read back at the next start. There is no setting for how often battles happen or for turning a battle type off; the original has none.
- 2026-11-18: every label and message the code draws comes from a translation key. The settings window title and its Default button, and the Dev mode "Show available exits" button on a site, were English text written in the code; they are keys now (`SrSettingsCategory`, `SrSettingsDefault`, `SrDevShowAvailableExits`), and the job line of `SrKillMelee` has an English `DefInjected` entry. Only English files gained keys; every existing translation is unchanged, so a player in another language sees these texts in English until a translator adds the keys (the game's own fallback).

### Known issues

- 2026-11-18: on the large site maps a player reaches by caravan (250 by 250 cells, about 50 pawns on each side), a battle sometimes stalls with both sides standing and no one winning, or one side leaves after almost no fighting. The cause is not yet found. A stalled site is removed after 90000 ticks.
